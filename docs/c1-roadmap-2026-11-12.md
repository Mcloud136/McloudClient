## 4. 后续计划（三条泳道）

### 4.1 主线 P1 — C1 收尾（按依赖排序）

| 编号 | 工作项 | 交付物 / 验收 | 依赖 |
|---|---|---|---|
| P1.1 | GUI 中文字体与主题定稿 | 字体方案（系统字体加载 vs 内嵌子集）实测 RSS 代价；设计 token 仍集中在 `theme.rs`；不突破 UI RSS ≤150 MiB | **需用户提供审美输入** |
| P1.2 | 系统代理接管 | 不提权、不动 TUN；设置/还原 Windows 系统代理，退出或崩溃时可靠还原；实机脚本验证「设置 → 上网 → 还原」 | 无（PoC 最小范围已明确「先系统代理」） |
| P1.3 | 托盘 / 最小化 / 自启 | 最小化时不跑 egui pass，空闲 CPU ≤0.2%（托盘预算）；开机自启接服务 | P1.2 |
| P1.4 | 订阅导入与配置管理 UI | GUI 从只读升为可写；订阅 URL **只在 Rust 控制面处理**，token 不进 UI 层；复用快照写入与 reload 事件 | P1.1；契约可能需增方法 |
| P1.5 | 安装器 v1（未签名） | MSI/EXE 完成服务注册、快照目录、默认 `live.json`、免手敲 CLI；升级 / 回滚接口留桩；复用 `install-service.sh` 的踩坑结论 | P1.2 / P1.3 |
| P1.6 | **C1 出口评审** | 全量回归 s5–s12 + DNS 无泄漏 + 强杀自愈 + 本机基准；20 min 窗口三项 CPU 分别计量；判定 §2 四项全部满足 | P1.2–P1.5 |

> P1.5 属系统级变更（注册服务），执行前按项目约定需用户确认。

### 4.2 并行线 P2 — 合规与基线（不阻塞主线，但越早越省事）

| 编号 | 工作项 | 关闭什么 |
|---|---|---|
| P2.1 | `cargo deny` / `cargo audit` 接入 CI；补齐 MPL-2.0（`v2node-proto`）、CC-BY-SA 2.0（GEOIP）、`wintun.dll` 声明 | G1 §8.3 第 3 条；C3 分发前置 |
| P2.2 | 量化投诉分布：面板机只读、7–30 天窗口，复用 `collect_client_ua.sh` 的聚合口径（只输出计数，不回显 token / IP / 原始日志行） | G1 §8.3 第 1 条；C2 内测验收输入 |
| P2.3 | D2 复核：WinTun 绑定候选的许可、成熟度、驱动内嵌形态；产出 DNS 无泄漏验收方案（含 Strict Route、DoH、WebRTC、UWP 用例） | 写生产 TUN 代码的前置 |
| P2.4 | ADR 0003 §6 性能顺序：真实链路基线 → 自身三层基线 → 解释 5 MiB 吞吐 5 倍波动 → 热点门控 | 性能优化的合法性前提；**需用户授权测试订阅** |
| P2.5 | C0b 第二步（角色解耦）、Go 对照组、W1 复核 | 服务端项目并行项，不依赖立项、可随时回退 |
| P2.6 | 多用户 IPC ACL 收紧（安装时写目标 SID） | 可选；当前 ACL 允许所有交互登录用户 |

### 4.3 主线 P3 — C2 MVP

按 `client-design-plan.md` §9：分流规则、自动更新、日志导出、连接诊断。

- **自动更新**（硬前置）：Ed25519 签名 manifest + 二进制 SHA-256 pin + 升级前记录快照 seq；
  60 s 健康检查失败自动回滚；保留上一版二进制与 5 版快照支持手动回滚。
  **必须在 FA 之前完成**，否则「升级 → 强制失败 → 回滚 → 转发正常」演练无法执行。
- **日志导出**：按契约 §6 第 3 条脱敏（节点地址、UUID、加密串、订阅链接）后才下发。
- **连接诊断**：复用 `nodes` / `probe_nodes`，补齐规划中的 `log_tail` / `diagnostics`。
- **分流规则**：GUI 可编辑规则 → 需扩展契约并验证快照兼容矩阵（新增字段可选或有默认值）。
- **出口**：10 人内测一周无 P0；同时验证「用户可自行切换探测策略与负载均衡策略」验收信号。

### 4.4 P4 — 功能冻结 → FA 最终验收

| 步骤 | 要求 |
|---|---|
| 冻结 | C0–C2 功能冻结，二进制 pin 版本并记录 SHA-256；冻结后任何代码变更使长稳数据失效、必须重跑 |
| 24 h 长稳 | RSS、句柄数、连接数、FD 上限、链路探测成功率；采样 ≤15 s；无线性泄漏、平台期斜率趋零、探测无持续失败 |
| 资源三项 | 内核 ≤0.2% / sidecar ≤0.3% / UI ≤1.0%（可见）、≤0.2%（托盘），20 min 窗口分别计量；**UI RSS ≤150 MiB** |
| 同时执行 | 全量回归（s5–s12 + CI 双平台）、脱敏复检、升级/回滚强制失败演练 |
| 环境阻塞 | `schtasks.exe` 仍被黑名单拦截 → 需手动挂机或放行 |

### 4.5 P5 — C3 发布

代码签名（EV/OV，私钥须硬件、证书有效期 460 天）、灰度通道、回滚预案、崩溃率与工单达标。
**证书采购是外部长周期项，建议现在启动，不要等 FA。**

### 4.6 延后 / 门控项

- **TUN**：仅在 P2.3 评审通过后写生产代码；提权只在内核服务，UI 不提权。
- C4 协议裁剪（0-RTT / 私有复用）、遥测（默认关闭）、自有 `v2node://` 订阅格式、
  多节点跨设备同步 —— 均不在本轮范围（预研 §8「明确不做」）。

## 5. 关键路径与依赖

```
P1.1 字体 ─────────────┐
P1.2 系统代理 ── P1.3 托盘 ── P1.5 安装器 ──┐
                        └─ P1.4 订阅导入 UI ──┼── P1.6 C1 出口
P2.1 许可 ──────────────────────────────────┘        │
P2.2 投诉分布 ────────────────────────── C2 内测输入   │
                                                      ▼
P3 自动更新 ────────────────────────────────► P4 功能冻结 ──► FA ──► P5 C3
P5 证书采购（外部长周期，与主线并行，现在启动）
P2.3 D2 复核 ───────────────────────────────► TUN（门控后，不阻塞 C1）
```

**三条硬约束**：

1. **自动更新先于 FA**：否则无法完成强制回滚演练，FA 不能通过。
2. **冻结后不改代码**：24 h 数据绑定二进制 SHA-256，任何修复都要重跑。
3. **真实链路基线需用户授权**：P2.4 与 C2 内测都依赖可用的测试订阅。

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 24 h 长稳被冻结后变更作废 | 高 | 冻结前完成全部功能；FA 期间禁止合入；变更即重跑 |
| 自动更新未完成导致 FA 卡住 | 高 | 把 P3 自动更新列为 FA 硬前置，提前做回滚演练脚本 |
| 签名证书采购 / 硬件密钥 | 中高 | 与主线并行，现在启动 |
| 中文字体推高 RSS 突破 150 MiB | 中 | P1.1 单独实测字体前后差值；绑定机器配置，不跨机型外推 |
| 安装器引入系统级变更 | 中 | 沿用 `install-service.sh` 已验证的绝对路径 / 管道转义结论；执行前用户确认 |
| GUI 从只读升为可写扩大 token 暴露面 | 中 | token 只在 Rust 控制面；契约 §6 脱敏边界不变；新增方法逐帧扫描 |
| 真实节点链路与本机 mock 基准结论不一致 | 中 | C2 内测单独验证测速 / 负载均衡语义，不用 mock 结论外推 |
| 现场问题归因不可执行（已接受） | 低 | 已由「可控可观测 + 本机可复现基准」替代，不再作为阻塞项 |
| 公开内存数字跨机器不可比 | 中 | FA 报告记录 GPU / 驱动 / 构建 SHA-256；阈值绑定本机 |

## 8. 推荐执行顺序（批次）

| 批次 | 内容 | 理由 |
|---|---|---|
| 第 0 批（已完成） | D1 裁决落地：预研 §11、设计文档预算、HANDOVER、记忆、本计划 | 决策固化，避免后续反复 |
| 第 1 批 | P2.1（许可扫描接入 CI）+ P2.2（量化投诉分布）+ P1.1 输入收集；同步启动 P5 证书采购 | 低成本、只读、关闭两条 G1 未决约束；不碰主线二进制 |
| 第 2 批 | P1.2 → P1.3 → P1.5 → P1.4 → P1.6 | 按依赖推进「单用户可用」，最后一个动作是 C1 出口评审 |
| 第 3 批 | P3 C2 MVP（自动更新优先）+ P2.3 / P2.4 并行 | 自动更新是 FA 硬前置；D2 复核不写生产代码 |
| 第 4 批 | P4 冻结 → FA → P5 C3 | 冻结后禁止变更；FA 全绿才进入签名分发 |

**建议的单一下一步**：从 **第 1 批的 P2.1 + P2.2** 开始 —— 两者都是只读 / CI 层改动，
可关闭 G1 两条未决约束，且不会让任何已冻结或待冻结的二进制失效。

## 9. 明确不做

- 不做 wgpu 后端复测、不重启 Tauri 对比、不引入 Zig / WebView 壳（D1 / D3 已关闭）。
- 不在 D2 与 DNS 无泄漏方案评审通过前写生产 TUN 代码。
- 不在 DIRECT 回环上先做性能优化（ADR 0003 §6）。
- 不把端到端公网测速作为代码效率验收口径（附录 C.1）。
- 不默认引入汇编（附录 C.3 门控未触发）、不默认开启遥测。
