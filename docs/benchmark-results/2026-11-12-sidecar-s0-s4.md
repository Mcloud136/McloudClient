## 2. S0：风险 R1 处理

**问题**：tokio 的命名管道 API 默认不暴露安全描述符，无法满足「仅 SYSTEM + 当前用户」。

**方案**：使用 tokio 1.54.1 的 `ServerOptions::create_with_security_attributes_raw`，配合 `ConvertStringSecurityDescriptorToSecurityDescriptorW` 构造保护型 DACL。

```
SDDL: D:P(A;;GA;;;SY)(A;;GA;;;<current_user_sid>)
实测: D:P(A;;FA;;;SY)(A;;FA;;;LA)
```

**验证**：创建管道 → `GetSecurityInfo` 读回 DACL → 断言包含 `SY` 与当前用户 → 客户端连接并收发成功。

**已知限制**：本地管理员账户的 SID 会被 Windows 规范化为组别名 `LA`（整个本地管理员组），标准用户保留原 SID。这是系统语义，需在设计文档中记录。

**未验证**：服务（session 0）↔ 用户（session 1）跨会话实测，需 Windows 服务封装后补做。

## 3. S1：协议与传输

| 项 | 实现 |
|---|---|
| 帧 | `u32` 大端长度 + UTF-8 JSON，上限 1 MiB |
| 消息 | `Request` / `Response` / `Event`，以 `type` 字段区分，均带 `v` |
| 抽象 | `IpcTransport` trait（`request` + `events`）、`Handler` trait |
| 传输 | 命名管道；客户端读写分离任务，关闭时通过 `watch` 通知读任务退出 |
| 测试 | 5 项协议（含超长帧拒绝）+ 2 项管道端到端 |

调试中发现的真实缺陷：`drop(client)` 只关闭写半部，读任务仍持有读半部导致服务端永远等不到 EOF。已用 `watch` 关闭信号修复。

## 4. S2：内核侧接口

`client-core` 新增 `--ipc-pipe <name>`，缺省不改变原有行为。

| 方法 | 行为 |
|---|---|
| `status` | 返回规则数、配置版本、运行时长；`detail=true` 时附 fake-ip 条目与来源 |
| `reload` | 复用「先构建、后替换」路径：拉取 → 构建 → 原子替换；失败保留旧路由 |
| 未知方法 | 返回 `unknown_method`，而非笼统错误 |

实测：`status` → `rules=4, version=0`；`reload` → `version=1`；未知方法返回 `unknown_method`。

## 5. S3：sidecar 与快照

| 能力 | 实现 |
|---|---|
| 引导快照 | 序号 0，仅 `MATCH,DIRECT`，保证首次启动不空配置 |
| 原子写 | `.tmp` → `fsync` → `rename` |
| current 指针 | 独立文件，原子替换 |
| live.json | 内核读取的固定路径，写入/回滚后同步 |
| 保留与回滚 | 保留 5 版，回滚到上一版 |
| 失败三态 | `fetch_failed` / `validate_failed` / `kernel_rejected` |

**过程中发现的第二个真实缺陷**：内核 `reload` 读取的是启动时固定的快照路径，而 sidecar 更新的是 `current` 指针，导致 `reload applied` 但规则数未变（4 → 4）。修复为「快照实体化为 `live.json`，内核读固定路径」，修复后规则数正确变为 5。

端到端：3/3 通过（内核由 sidecar 启动、源变更触发 reload、快照目录完整）。

## 6. S4：IPC 基准

| 指标 | 实测 | 预算 | 结论 |
|---|---|---|---|
| RTT P50 | 112 µs | — | — |
| RTT P95 | 244 µs | — | — |
| RTT P99 | **307 µs** | ≤ 5 ms | 通过（约 16× 余量） |
| 最大 | 380 µs | — | — |
| 空闲 CPU | **0.000%**（30 s） | ≤ 0.5% 单核 | 通过 |

样本 1000 次，同机、Debug 构建。**共享内存替换的触发条件全部未命中**，控制面维持命名管道。

## 7. 未覆盖项

| 项 | 原因 | 建议 |
|---|---|---|
| 事件推送（`applied` / `rejected`） | 当前为请求-响应，事件通道已就绪但未接内核 | 用读写分离任务实现，避免 `select!` 取消导致帧错位 |
| 跨会话 | 需 Windows 服务封装 | 服务化后补测 |
| 订阅 URL | sidecar 目前只读本地文件 | 复用内核的 HTTP 拉取或引入 reqwest |
| supervisor 退避 | 仅检测内核退出并退出 sidecar | 完整重启策略与崩溃计数 |
| 安装器 | 未开始 | 分发阶段 |
