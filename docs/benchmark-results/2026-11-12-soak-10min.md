# client-core 10 分钟长稳采样（2026-11-12）

> 目的：为 **FA 最终验收**的「24 h 无内存增长」提供代理指标，并建立可复现的采样方法（2026-11-12 流程调整后，该项已移出 C0d）。
> 结论：**未观察到线性泄漏**；存在一次性台阶（首次转发）与约 0.8 MB / 8.5 min 的缓慢上升。**24 h 未执行**，不足以证明长稳；该数据须在所有功能冻结后的 FA 阶段采集。

## 1. 方法

| 项 | 值 |
|---|---|
| 程序 | `client-core` 0.1.0（commit `9f6e141`） |
| 配置 | 单加密入站、规则 `MATCH,proxy`、fake-ip DNS 开启 |
| 时长 | 600 s（实际采样 585 s） |
| 内存/句柄采样 | 每 15 s，`Get-Process` 的 `WorkingSet64` 与 `HandleCount` |
| 链路探测 | 每 60 s 一次 `curl --socks5-hostname https://api.ipify.org`，记录成功与耗时 |
| 日志级别 | `RUST_LOG=warn`（避免日志缓冲影响内存） |

## 2. 结果

| 指标 | 数值 |
|---|---|
| RSS 首次 | 14,344 KB（14.0 MiB） |
| RSS 末次 | 21,000 KB（20.5 MiB） |
| RSS 峰值 | 21,040 KB（20.5 MiB） |
| RSS 增长 | +6,656 KB（+46.4%） |
| 句柄 | 168 → 203（+35） |
| 探测 | **8/8 成功** |
| 探测耗时 | 平均 3,875 ms，最大 4,341 ms |

## 3. 阶段特征

| 区间 | 行为 |
|---|---|
| 0–60 s | 14.3 MB 稳定，句柄 168 |
| 60–75 s | 首次真实转发后跳至 20.2 MB，句柄 203（+5.9 MB / +35） |
| 75–585 s | 20.2 → 21.0 MB，增量约 0.8 MB，多数采样在 20.7–21.0 MB 间波动 |

一次性台阶出现在**首次 TCP 转发**之后，属于 TLS/WS 缓冲与连接池的首次分配；此后无明显单调增长。

若以 0.8 MB / 510 s 的斜率线性外推，24 h 约 135 MB——但该斜率更像分配器波动而非持续泄漏，**必须用 24 h 数据判定**，不能外推。

## 4. 复现方式

```bash
# 10 分钟基线
SOAK_SECONDS=600 python soak.py

# 24 h（建议由独立任务/计划任务运行，避免会话结束被回收）
SOAK_SECONDS=86400 python soak.py
```

输出：`soak.csv`（逐样本）与 `soak-summary.json`（汇总）。脚本与凭据均在仓库外，profile 不入库。

## 5. 结论与限制

- 10 分钟窗口内链路连续性 8/8，无中断。
- 内存与句柄在首次连接后进入平台期，未见持续泄漏特征。
- 延迟 3.4–4.3 s 为「TLS + mlkem 握手 + 经 Cloudflare」的单次冷请求耗时，不代表数据面吞吐。
- **FA 最终验收待执行**：24 h 数据缺失，且未采集句柄泄漏、连接数、FD 上限等长期指标。该项已不再属于 C0d 通过线。
